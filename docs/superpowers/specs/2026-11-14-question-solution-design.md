# 题解与分层提示设计

## 目标

在做题工作台的“题解”页签中提供可审核的题解社区，同时严格防止未通过用户从前端页面或接口响应中获取完整答案。

## 已确定规则

- 用户必须在当前题目上存在 `status = 2` 且 `judge_info.message = "Accepted"` 的提交，才能创建、修改、提交审核和阅读完整题解。
- 管理员不受 AC 限制，可以审核、驳回、设置官方题解和查看所有内容。
- 未通过或未登录用户可以看到已发布题解的标题、作者、摘要和单独编写的“安全提示”，但接口不返回完整正文、完整代码或评论。
- 题解正文与安全提示必须分字段存储；不使用“截取正文前几行”生成提示，避免泄露关键算法或完整代码。
- 普通用户提交后进入待审核；管理员通过后才对外显示。已发布题解被作者修改后自动回到待审核。
- 只有已通过用户和管理员能查看/发表评论、点赞题解，防止评论区间接泄题。
- 同一用户在同一题目上只保留一篇题解，可重复修改和重新提交审核。

## 数据模型

### `question_solution`

保存题解主体：题目、作者、标题、摘要、安全提示、Markdown 完整正文、审核状态、官方标识、审核人与原因、浏览/点赞/评论计数。审核状态为 `0 草稿 / 1 待审核 / 2 已发布 / 3 已驳回`。

### `question_solution_like`

保存用户对题解的点赞，`solution_id + user_id` 唯一，切换点赞在事务中同步维护题解计数。

### `question_solution_comment`

保存一级评论和回复，支持软删除。评论仅在完整题解可见时返回。

## 后端权限与接口

- 新增统一的 `QuestionSolutionAccessService` 检查 AC 资格和管理员身份，所有题解读写接口必须通过该服务，不依赖前端传入的角色。
- `GET /question-solution/problem/{questionId}/eligibility`：返回是否已通过、是否可写、是否可看完整内容。
- `POST /question-solution/problem/page`：搜索当前题目已发布题解；普通访客只获得预览字段。
- `GET /question-solution/{id}`：根据访问级别返回 `HINT` 或 `FULL`；`HINT` 响应的 `content` 必须为 `null`。
- `GET/POST /question-solution/mine`、`/save`、`/submit-review`、`/delete`：作者操作，要求 AC。
- `POST /question-solution/{id}/like/toggle` 与评论接口：要求 AC 或管理员。
- `/question-solution/admin/page`、`/review`、`/official`：管理员审核和标记官方题解。
- 题解列表仅计算已发布数据；作者可在“我的题解”查看自己的草稿、待审和驳回原因。

## 前端交互

- 题解页签改为独立 `ProblemSolutionPanel` 组件，不再继续扩大做题页主文件。
- 顶部包含题解数、搜索框和“写题解”按钮。未通过时按钮显示锁定说明，引导用户先完成题目。
- 列表卡片显示官方标签、标题、摘要、作者头像、浏览、点赞、评论和时间，优先展示官方题解。
- 未通过用户打开卡片后进入“学习提示”视图，只渲染安全提示，并明确说明通过后可解锁完整题解。
- 已通过用户可查看 Markdown 正文、评论、点赞，并在当前页编写或编辑自己的题解。
- 作者保存草稿、提交审核和看到驳回原因；页面提示“安全提示不应包含可直接提交的完整代码”。

## 数据库交付

- 将三张表的幂等 DDL 合并到 `spingboot-init/src/main/resources/db/schema.sql`。
- 新增一次性升级 SQL `spingboot-init/src/main/resources/db/migrations/20261114_question_solution.sql`，供已有生产库执行。
- 服务器上单独上传的 SQL 执行成功后可删除；仓库内的迁移文件保留，用于追溯数据库版本。

## 安全与验收

- 未通过用户、匿名用户、伪造管理员字段的请求都不能获得完整正文。
- 用户 A 通过不能使用户 B 获得权限；他题 AC 不能解锁当前题。
- 待审、驳回和草稿不得出现在公开列表。
- 已发布题解修改后必须重新审核；驳回原因仅作者和管理员可见。
- 点赞不得重复计数，删除评论与题解后计数保持一致。
- 所有 BIGINT ID 继续以字符串返回前端，避免 JavaScript 精度丢失。

# 五类图像编程题多策略判题设计

## 定位

系统采用一套统一的图像用例传输、只读挂载和 Docker 沙箱执行流程，并根据题型选择五种输出协议与判题策略。图像目标计数题是核心成果，分类、检测框、OCR 和数值分析为扩展能力。

## 协议

- `IMAGE_CLASSIFICATION`：主目标标签分类题。使用 YOLO 检测结果中置信度最高的目标类别；无目标为 `unknown`；忽略大小写与首尾空格匹配。
- `IMAGE_OBJECT_COUNT`：类别到数量的 JSON 对象，逐类别比较并使用独立数量误差。
- `IMAGE_OBJECT_DETECTION`：`label/x1/y1/x2/y2` JSON 数组，坐标归一化到 0～1，按类别、框数量和 IoU 判定。
- `IMAGE_OCR`：纯文本，规范化空格和标点后按编辑距离判定。
- `IMAGE_ANALYSIS`：固定输出 `width/height/mode/mean_gray/edge_strength`，尺寸和模式精确匹配，两个数值字段使用独立误差。

## 配置兼容

语义配置写入现有 `judge_config` JSON：

```json
{
  "countTolerance": 1,
  "iouThreshold": 0.5,
  "ocrEditDistance": 2,
  "meanGrayTolerance": 0.5,
  "edgeStrengthTolerance": 1.0
}
```

历史题仅有顶层 `count_tolerance` 时继续按旧语义读取；新题优先读取语义字段。公开样例运行、发布预检和正式提交必须调用同一套解析规则。

## 命题安全

- 至少一组公开用例、一组隐藏用例、两张不同图片；界面推荐一公开两隐藏。
- Vision AI 只生成候选结果，必须由教师人工确认后才能发布。
- 学生端不返回隐藏图片、标准输出、检测详情或内部沙箱信息。
- 发布前校验输出协议、模型与题型组合、人工确认状态和多图片固定输出风险。

## 页面

教师端按“深度学习目标识别 / 文字识别 / 传统计算机视觉”分组，展示题型说明、输出示例、适用场景和判题方式；只显示当前题型需要的参数。

## 证据边界

构建与单元测试不等于真实服务链路验证。mAP、OCR 准确率、人工标注一致率、20 人并发和 4GB 服务器性能若无真实记录，统一标记为“待实验验证”。
